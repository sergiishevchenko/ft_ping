# Флаги командной строки (`ft_ping`)

Справочник по всем опциям командной строки **ft_ping**. Формат вывода и поведение — как у **inetutils-2.0** (`ping -V` на Debian). Парные команды для сравнения с системным `ping` — в [`../TESTING.md`](../TESTING.md).

## Общие правила

| Правило | Детали |
|---------|--------|
| Цель | Ровно **один** hostname или IPv4 (позиционный аргумент) |
| Протокол | Только **IPv4** ICMP Echo (`SOCK_RAW`, `IPPROTO_ICMP`) |
| Права | Raw-сокет → **root** (`sudo ./ft_ping …`) |
| Строки ответа | Показывать **IP источника** — **без reverse DNS** |
| Частота по умолчанию | Один пакет в **секунду** (`interval = 1 000 000` мкс) |
| Payload по умолчанию | **56** байт data (заголовок ICMP 8 → в ответе **64 bytes**) |
| ICMP id | `getpid() & 0xFFFF` |
| Остановка | `Ctrl+C` (SIGINT) или флаги `-c`, `-w`; затем статистика |
| Эталон | inetutils `ping` на Debian VM |

## Обязательные флаги

### `-?` и `--help`

| | |
|---|---|
| **Назначение** | Справка **без** root |
| **Синтаксис** | `./ft_ping -?` или `./ft_ping --help` |
| **Поведение** | Список опций, выход с кодом **0** |
| **Реализация** | `print_usage()` в `main.c`, до создания сокета |
| **Пример** | `./ft_ping -?` |

---

### `-v` (verbose)

| | |
|---|---|
| **Назначение** | **Обязателен.** Показывать ICMP-проблемы, связанные с **вашими** пакетами, и расширенную диагностику |
| **Синтаксис** | `-v` |
| **Поведение** | |
| | • В заголовке — **id** эха: `… id 0xHHHH = NNNN` |
| | • **ICMP-ошибки** (TTL exceeded и т.д.) для пакетов **к цели** всегда видны |
| | • Без `-v` чужие ICMP-ошибки (другой inner dst) **фильтруются** |
| | • При ошибках — блок **`IP Hdr Dump:`** и внутренний ICMP |
| **Типичный тест** | `sudo ./ft_ping --ttl 1 -c 3 8.8.8.8` и с `-v` |
| **Реализация** | `OPT_VERBOSE` в `print.c`, `stats.c` |
| **Пример** | `sudo ./ft_ping -v -c 2 127.0.0.1` |

## Бонусные флаги

### `-c <count>`

| | |
|---|---|
| **Назначение** | Остановиться после `<count>` **уникальных** echo-ответов |
| **Синтаксис** | `-c <N>` |
| **По умолчанию** | `0` = до Ctrl+C или `-w` |
| **Поведение** | |
| | • Считаются **уникальные** ответы: `(num_recv - num_rept) >= count` |
| | • Дубликаты `(DUP!)` **не** входят в лимит |
| | • После отправки `count` пакетов — ожидание до **`-W`** сек |
| **Пример** | `sudo ./ft_ping -c 3 127.0.0.1` |

---

### `-s <size>` (размер payload)

| | |
|---|---|
| **Назначение** | Размер **data** ICMP в байтах (без 8-байтного заголовка ICMP) |
| **Синтаксис** | `-s <N>` (`0` … `65507`) |
| **По умолчанию** | `56` |
| **Поведение** | |
| | • Заголовок: `PING …: <N> data bytes` |
| | • В ответе `bytes` = **8 + N** |
| | • При `N >= 16` первые 16 байт — `timeval` для RTT |
| | • При `N == 0` в ответе **нет** `time=… ms` |
| **Примеры** | `-s 0` → `8 bytes`; `-s 1000` → `1008 bytes` |

---

### `-w <timeout>` (deadline)

| | |
|---|---|
| **Назначение** | Стоп через `<timeout>` **календарных** секунд от старта |
| **Синтаксис** | `-w <N>` |
| **По умолчанию** | выкл. |
| **Поведение** | Выход из цикла, печать статистики |
| **Пример** | `sudo ./ft_ping -w 2 8.8.8.8` |

---

### `-W <linger>`

| | |
|---|---|
| **Назначение** | После отправки всех пакетов по `-c` ждать ответы ещё `<linger>` секунд |
| **Синтаксис** | `-W <N>` |
| **По умолчанию** | `10` |
| **Пример** | `sudo ./ft_ping -c 2 -W 3 8.8.8.8` |

---

### `--ttl <N>`

| | |
|---|---|
| **Назначение** | IP **Time To Live** исходящих пакетов |
| **Синтаксис** | `--ttl <N>` (`0` … `255`) |
| **По умолчанию** | `64` |
| **inetutils** | `-t <N>` |
| **Поведение** | `--ttl 1` к удалённому хосту → **Time to live exceeded** от роутера |
| **Примеры** | `sudo ./ft_ping --ttl 1 -c 3 8.8.8.8` |

---

### `-T <tos>`

| | |
|---|---|
| **Назначение** | Байт **TOS** в IPv4-заголовке |
| **Синтаксис** | `-T <N>` (`0` … `255`) |
| **Поведение** | `setsockopt(IP_TOS)`; сеть может игнорировать TOS |
| **Пример** | `sudo ./ft_ping -T 16 -c 1 127.0.0.1` |

---

### `-f` (flood)

| | |
|---|---|
| **Назначение** | Отправка как можно чаще |
| **С `-f`** | interval **10 мс**; `.` при send, `\b` при ответе — **без** строк на пакет |
| **Пример** | `sudo ./ft_ping -f -c 100 127.0.0.1` |

---

### `-l <preload>`

| | |
|---|---|
| **Назначение** | Первые `<preload>` пакетов отправить **подряд** без паузы |
| **Пример** | `sudo ./ft_ping -l 10 -c 10 127.0.0.1` |

---

### `-p <hex>` (pattern)

| | |
|---|---|
| **Назначение** | Заполнить payload (после timestamp) **hex**-шаблоном |
| **Синтаксис** | до **16** байт; нечётная длина hex допустима |
| **Ошибка** | не-hex → `error in pattern near '…'`, exit ≠ 0 |
| **Примеры** | `-p ff -s 56 -c 1 127.0.0.1`; `./ft_ping -p zz 127.0.0.1` |

---

### `-n` (numeric)

| | |
|---|---|
| **Назначение** | Числовой вывод — без DNS в строках **ответа** |
| **Поведение** | Цель может быть hostname (forward DNS); в ответах только IP |
| **В проекте** | Reverse DNS не используется; флаг принят для совместимости с inetutils |
| **Пример** | `sudo ./ft_ping -n -c 1 google.com` |

---

### `-r` (bypass routing)

| | |
|---|---|
| **Назначение** | Обход таблицы маршрутизации (`SO_DONTROUTE`) |
| **Пример** | `sudo ./ft_ping -r -c 1 127.0.0.1` |

---

### `--ip-timestamp <flag>`

| | |
|---|---|
| **Назначение** | IP-опция **timestamp** в исходящих пакетах |
| **Значения** | `tsonly` или `tsaddr` |
| **Вывод** | Блок `TS:` (и `RR:` при наличии) |
| **Сеть** | Часто опции отбрасываются → loss нормален; краш недопустим |
| **Примеры** | `sudo ./ft_ping --ip-timestamp tsonly -c 1 8.8.8.8` |

---

## Позиционный аргумент `<destination>`

Один IPv4 или hostname. Заголовок сохраняет **введённую строку**: `PING google.com (x.x.x.x): …`. Ошибки: нет аргумента, unknown host, только один хост.

## Код выхода

| Условие | Код |
|---------|-----|
| Help | `0` |
| Есть хотя бы один ответ | `0` |
| Нет ответов | `1` |
| Ошибки разбора / сокета / pattern | ≠ 0 |
